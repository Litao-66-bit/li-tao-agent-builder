# 04 · 错误码体系

统一错误分类，是返工、中断、审计、用户提示的基础。错误码为 4 位数字，前两位大类。

## 错误码表

| 错误码 | 名称 | 含义 | 触发者 | 处理策略 |
| --- | --- | --- | --- | --- |
| `1000` | `E_PERMISSION` | 越权：路径出白名单 / 工具未授权 / 角色越职 | 工具门卫 | 拒绝 + 审计 + 上报审计员；不重试 |
| `2000` | `E_TIMEOUT` | 执行超时（工具/步骤/模型调用） | Conductor | 重试 1 次，仍超时转失败或跳过（按 fallback） |
| `3000` | `E_VALIDATION` | 格式/校验失败：DAG 非法、JSON 解析失败、计划含环 | 规划/验证组 | 打回生产方修正（计入 retry_count） |
| `4000` | `E_MODEL` | 模型错误：幻觉被拦截、输出截断、API 报错 | 验证组/门卫 | 拦截输出；截断重试 1 次（结构化输出） |
| `5000` | `E_TOOL` | 工具异常：检索无结果、依赖安装失败、数据缺失 | 执行者/门卫 | 换通道重试 1 次，仍失败上报 |
| `6000` | `E_USER_CANCEL` | 用户中断或拒绝审批 | 用户 | 任务转 `interrupted`，保留 resume_point |
| `7000` | `E_COST` | 成本超限：LLM 调用次数/预估 token 达预算上限 | 预算闸门（BudgetTracker） | 任务中止，上报；不重试，需调整预算后重跑 |
| `9000` | `E_INTERNAL` | 内部错误：状态机非法转换、消息类型未知 | Conductor | 任务转 `failed`，记录日志 |

## 错误消息体

```json
{
  "error_code": 3000,
  "error_name": "E_VALIDATION",
  "message": "步骤 DAG 存在环依赖：step-003 -> step-001",
  "source": "scheduler",
  "retryable": true,
  "correlation_id": "c-..."
}
```

## 规则

1. `retryable=true` 的错误允许重试 1 次；`false` 一律直接上报，不消耗 retry_count。
2. `E_PERMISSION` 永不重试——越权不是偶然故障，必须人工介入。
3. `E_COST` 永不重试——预算超限重试只会继续消耗资源，必须调整预算后重跑。
4. 所有错误必须带 `correlation_id`，进入审计日志。
5. 用户界面提示由错误码映射（如 6000 → "已暂停，随时可恢复"；7000 → "预算超限，任务中止"）。
